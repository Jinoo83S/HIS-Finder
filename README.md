# HIS Finder

GitHub Pages에서 학생 검색 화면과 공개 반 시간표를 제공하고, 기존 `his-main` Firebase에서 학교 계정 로그인 및 학생별 시간표 검색을 처리합니다. Apps Script는 출결·보건실 조회, 시트 동기화 및 공개 시간표 게시를 담당합니다. 기존 Spark 프로젝트를 사용합니다.

## 백엔드 배포

1. Firebase 콘솔의 **his-main → Firestore Database → 규칙**에서 기존 `match /databases/{database}/documents { … }` 안에 [HIS Finder 추가 규칙](firestore-rules-addition.txt)을 넣고 게시합니다. 기존 규칙을 포함한 상태에서 Finder 규칙만 추가합니다. 규칙의 관리자 이메일은 아래의 `ADMIN_EMAIL`과 일치해야 합니다.
2. 세 원본 시트에 읽기 권한이 있는 학교 계정으로 **새 독립형 Apps Script 프로젝트**를 만듭니다. 기존 웹 앱은 그대로 운영하면서 새 프로젝트를 테스트할 수 있습니다.
3. `apps-script/Code.gs`와 `apps-script/appsscript.json`을 추가합니다. 매니페스트가 보이지 않으면 프로젝트 설정의 매니페스트 표시를 켭니다. 프로젝트 설정의 **스크립트 속성**에 다음 값을 입력합니다.

   | 이름 | 값 |
   | --- | --- |
   | `FIREBASE_WEB_API_KEY` | `his-main` Firebase 웹 앱 설정의 `apiKey` |
   | `ADMIN_EMAIL` | 기본 관리자 학교 이메일 |
   | `SOURCE_URLS` | `{"courses":"…","schedule":"…","attendance":"…","clinic":"…"}` 형태의 원본 주소. 수강 명단과 수업 배정은 같은 문서를 지정할 수 있습니다. |
   | `FIREBASE_LOOKUP_API_KEY` | 선택 사항. 웹 키가 HTTP 리퍼러로 제한된 경우, 같은 Firebase 프로젝트에서 서버의 Identity Toolkit 계정 조회를 허용하는 별도 키를 여기에 지정합니다. |
   | `GITHUB_TIMETABLE_TOKEN` | 공개 게시에만 필요합니다. `Jinoo83S/HIS-Finder` 하나로 범위를 제한한 fine-grained 토큰의 `Contents: Read and write` 권한이 필요합니다. |
   | `GITHUB_BRANCH` | 선택 사항. 공개 파일을 올릴 Pages 소스 브랜치입니다. 기본값은 `main`입니다. |

4. **배포 → 새 배포 → 웹 앱**에서 **다음 사용자로 실행 → 나**, **액세스 권한 → 모든 사용자**(로그인 전 호출 가능)를 선택합니다. 공개 진입점은 버전과 Firebase 웹 설정만 제공하며, 학생 자료와 관리자 기능은 서버에서 Firebase 토큰 및 학교 이메일을 확인합니다. 조직 정책으로 이 옵션이 숨겨져 있으면 조직에서 허용하는 배포 경로가 필요합니다.
5. 새로 발급된 `/exec` URL을 열어 `version: 2` 응답을 확인하고, 해당 주소를 `config.js`에 저장합니다. Firebase Authentication의 승인된 도메인에 GitHub Pages 호스트가 포함되어 있는지 확인합니다.
6. 새 화면에서 관리자 로그인 후 **시트 탭·헤더 확인**을 실행합니다. 탭 이름은 지정 시 우선하며, 비어 있으면 URL의 `gid`로 찾습니다. 학기를 입력하고 **설정 저장 → 시간표 연동**을 실행하면 학생 검색이 활성화됩니다.
7. **공개 시간표 미리보기**로 행 전체를 확인하고 **GitHub에 공개**를 선택합니다. 공개 파일은 Pages 소스 브랜치의 `timetable.json`에 올라갑니다. 미리보기 이후 시트가 바뀐 경우 다시 미리보기해야 합니다. 토큰은 Apps Script 속성에만 보관합니다.

## 원본 시트 구조

| 구분 | 기본 구조 | 처리 |
| --- | --- | --- |
| 수강 명단 | `Raw_Cou` A 이름, B 학년, C 반, J 번호, K–N 과목명, Q 수강 코드 | 학기별 관리자 연동 |
| 수업 배정 | `시간표_Data` A 학년, B 반, C 요일, D 교시, E 수강 코드, F 교사, G 교실, I 예비교실 | 학기별 관리자 연동 |
| 출결 | 이름·날짜·출결 상태 열 또는 날짜별 열. 학년·반·번호·교시·시간이 있으면 함께 매핑 | 오늘 자료 최대 60초 캐시. 학생 화면에서 30초마다 확인, 수동 새로고침 시 즉시 읽기 |
| 보건실 | 이름·방문 날짜 열. 학년·반·번호가 있으면 함께 매핑 | 조회마다 원본을 읽고 오늘 방문 여부만 반환 |

출결과 보건실은 헤더를 자동 인식하며, 필요한 경우 열 위치를 지정할 수 있습니다. 예를 들어 `NAME=B,DATE=A,STATUS=E,PERIOD=F`를 입력합니다. 날짜는 연도를 포함해야 합니다. 동명이인을 식별할 수 없는 기록은 확인 필요로 표시합니다.

시간표 연동은 학생별 검색 자료를 `finderConfig`와 `finderSnapshots`에 기록하며, 당일 기록의 동명이인 확인용 명단 스냅샷은 실행 계정의 스프레드시트에 저장합니다. 소스 구조를 바꾸면 탭 및 열을 다시 확인하고 시간표를 수동으로 재연동합니다. 관리자 설정에서 중·고등별 월–목, 금요일, 단축수업 시간과 단축수업 날짜를 변경할 수 있습니다.

공개 파일에는 학기, 반, 요일, 교시, 과목명, 교실과 표시 항목에서 생성한 키를 담습니다. 과목명을 확인할 수 있는 시간표 행을 게시합니다. 학교 계정으로 학생 이름과 개인별 시간표를 읽을 수 있으며, 쓰기는 지정된 관리자만 가능합니다. 실제 전환 전 학교 계정과 외부 계정, 관리자 설정, 동명이인, 당일 출결 변경을 확인하세요.
